# RAG Experiment Register

## Public-data limitation

The assignment's definitive hypothesis remains: requirement decomposition plus hybrid retrieval and
reranking should raise evidence Recall@5 over naive dense retrieval on jobs with multiple requirements,
without increasing unsupported claims after verification. This hypothesis must be tested on the
self-authored persona/dev set; no public job dataset provides its gold portfolio evidence.

## Synthetic plumbing study (preregistered before execution)

Hypothesis: on 90 deterministic jobs, 30 for each synthetic AI/ML, full-stack and data-analyst persona,
V1 requirement decomposition, V2 hybrid retrieval and V3 reranking will each match or exceed V0
Recall@5, while V8 will refuse weak evidence rather than increasing unsupported claims. Results from
this study validate experiment plumbing and reveal implementation regressions only. They are labelled
`synthetic` in the dataset and result file and must not be presented as real freelancer performance or
GigSim outcomes.

Planned metrics are Recall@5, MRR, nDCG@10, p50/p95 retrieval latency, unsupported claims before and
after verification, all broken down by persona. Each job has ten relevant evidence items from the same
project: case study, repository README, code sample, review and six successful/replied-to proposals.
The remaining project material and ignored proposals are distractors. Recall@5 therefore has a maximum
of 0.5. The verifier is tested twice: first on the normal writer output and then on a deliberately
injected, uncited guarantee. The latter is an attack test, not normal writer behaviour.

## Synthetic result

Regenerated on 2026-11-12 with `gigbid-personas-v1`; the complete machine-readable output is
`evals/results/synthetic_rag.json`.

| Variant | Recall@5 | MRR | nDCG@10 | p95 latency (ms) | Normal unsupported before/after | Seeded attack before/after |
|---|---:|---:|---:|---:|---:|---:|
| V0 naive | 0.494 | 0.989 | 0.738 | 2.5 | 0 / 0 | 1 / 0 |
| V1 requirements | 0.378 | 0.664 | 0.662 | 17.0 | 0 / 0 | 1 / 0 |
| V2 hybrid | 0.500 | 1.000 | 0.801 | 120.4 | 0 / 0 | 1 / 0 |
| V3 rerank | 0.498 | 1.000 | 0.749 | 120.4 | 0 / 0 | 1 / 0 |
| V8 corrective | 0.378 | 0.664 | 0.662 | 17.1 | 0 / 0 | 1 / 0 |

The preregistered hypothesis failed because V1 scored below V0. V2 reached the benchmark's maximum
Recall@5 and improved ranking quality at substantially higher latency. The likely diagnosis is that
the current requirement-wise fusion overweights repeated broad terms in this templated corpus. This is
a development finding, not evidence about real marketplace outcomes. The next experiment should tune
fusion on a training split and then test once on a held-out authored set. These synthetic labels must
remain clearly separated from real marketplace evidence.

## V2 component ablation

`python -m evals.runners.rag_ablation` removes one V2 component at a time on the same 90-job set.
The complete per-persona, per-job-type and row-level output is
`evals/results/rag_ablation.json`.

| Configuration | Recall@5 | MRR | nDCG@10 | p95 latency (ms) |
|---|---:|---:|---:|---:|
| Dense only | 0.493 | 0.983 | 0.742 | 2.5 |
| Lexical only | 0.500 | 1.000 | 0.833 | 180.2 |
| Type-diverse hybrid RRF | 0.500 | 1.000 | 0.801 | 182.6 |

The component hypothesis also failed: lexical-only retrieval was 0.032 nDCG better than the shipped
type-diverse hybrid on the templated synthetic labels. This is useful negative evidence. V2 still ships
because it reaches maximum Recall@5, retains a semantic path for paraphrases, and caps past-proposal
dominance so case studies, code and reviews reach the writer. The report does not claim that fusion won.
